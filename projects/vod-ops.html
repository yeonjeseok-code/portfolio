01

시간 부족을 사람의 추가 투입으로 풀지 않다

여러 카테고리의 강의를 직접 확인하며 수강 만족도와 과제의 적절성을 판단해야 했습니다. 카테고리마다 확인할 내용도 달라 기획자가 모든 강의를 보고 문제를 찾아 수정 요청을 남기는 데 많은 시간이 필요했습니다.

다른 기획자와 나눠 맡더라도 강의를 전부 확인해야 하는 일 자체는 줄어들지 않았습니다. 누가 검수할지보다 이미 강의를 확인해야 하는 사람이 누구인지 먼저 살폈습니다.

판단의 기준

어차피 해야 하는 학습과 검수를 연결할 수 있을까?

수강생은 강의를 수강해야 했고 멘토는 과제 피드백을 위해 내용을 숙지해야 했습니다. 이들의 확인 시점을 앞당겨 피드백을 받으면 기획자가 혼자 반복 확인하는 부담을 줄일 수 있다고 판단했습니다.

02

담당한 역할

검수 업무의 문제를 정리하고 테스터와 멘토가 참여하는 프로세스를 처음부터 기획했습니다. 각 참여자의 역할과 확인 시점 및 피드백 문서의 기준을 설계했습니다.

운영팀의 체크리스트와 테스터 선정 기준을 정리하고 기획자와 연사가 개선 사항을 검토할 흐름을 문서화했습니다.

03

판단과 실행

  1. 운영 구조 문제 분석 검수/개선을 한 사람이 모두 담당하는 구조 피드백 기준 부재 기술적 문제와 커리큘럼 문제가 섞여 있는 상황을 정리하고 협업 흐름 상 데이터 기반 판단이 어렵다는 점을 명확히 했습니다.
  2. 새로운 프로세스 설계 멘토 사전 콘텐츠 숙지 → 주차별 피드백 초안 작성 → n-1주차 테스터 확인 → 정규 수강생 반응 기반 최종 피드백으로 이어지는 2중 피드백 구조를 설계했습니다. 기술적 편집 vs 커리큘럼 문제를 분리하는 기준을 만들고 개선 사항을 A+2 기수까지 반영하는 루프를 만들었습니다.
  3. 역할과 협업체계 설계 (R&R) 멘토와 수강생과 기획자와 운영과 연사의 역할을 분리하고 문서화했습니다. 운영팀 체크리스트와 설문 구조를 재설계해 R&R 기반 주차별 개선 흐름을 정렬했습니다.
  4. 문서화 & 시각화 Mermaid 타임라인과 텍스트 기준을 한 문서 구조로 통합하고 신규 PM 또는 기획자가 바로 온보딩할 수 있도록 가이드를 제작했습니다.
04

테스터와 멘토의 협업 흐름

TESTER STUDENTS

먼저 수강하고 문제를 남기다

  1. 선정과 안내

    운영팀의 사전 설문과 선정 기준을 거쳐 참여 방법을 안내합니다.

  2. 한 주 먼저 확인

    정규 수강 일정에 앞서 콘텐츠를 확인하고 피드백과 타임스탬프를 제출합니다.

  3. 수강 경험 종합

    실제 수업과 멘토링 참여 후 전체 주차의 피드백을 정리해 기획자에게 전달합니다.

MENTORS

실제 반응을 읽고 개선을 잇다

  1. 사전 숙지

    커리큘럼과 콘텐츠를 확인하고 주차별 관찰 기준을 정리합니다.

  2. 반응 관찰

    멘토링에서 드러나는 수강생 반응을 바탕으로 최종 피드백을 작성합니다.

  3. 개선 협의

    기획자 및 연사와 수정 여부를 검토하고 A+2 기수까지 반영할 사항을 정리합니다.

05

운영에 적용한 변화

역할 분담

기획자 중심 → 참여형 검수

기획자가 오롯이 담당하던 콘텐츠 확인을 테스터 수강생과 멘토에게 분담했습니다. 기획자는 모인 피드백을 바탕으로 개선을 조율했습니다.

판단 기준

기술 문제와 커리큘럼 문제 구분

수정 요청을 같은 종류로 취급하지 않고 편집 및 기술 문제를 내용 구성 문제와 나누어 담당자가 확인하도록 정리했습니다.

반영 시점

피드백이 다음 기수로 이어지도록

주차별 확인부터 피드백 제출과 개선 반영 시점까지 문서로 연결해 한 번의 검수로 끝나지 않는 흐름을 만들었습니다.
